# UnderwaterRobotGroundControl Frontend

简称：URGC。

这是 Vue 3 + TypeScript + Vite 的只读遥测前端。当前只读取 URGC 核心状态，不提供电机、
回零、PID、参数下发等写操作。页头、浏览器标签和安装到桌面的图标统一使用无文字版
`public/Redbird.png`；`public/Redbird-source.png` 保留用户提供的原始竖版素材。

当前工作台按普通笔记本和外接显示器布局，验收视口为 1280×720、1366×768 和
1920×1080。操作页占满浏览器视口，表格和日志在各自面板内部滚动。默认进入主页，
通过“工作台侧栏”切换四个任务页：

- 主页：设备概览和工作台入口，沿用同一份真实遥测状态。
- 运行监控：姿态/深度、目标-反馈-误差表、蜗杆与浮力系统、短时趋势、连接事件。
- 遥测诊断：按 UGEKF/UGCTL/UGWRM 切换中文字段表，可筛选字段并查看原始快照。
- 会话记录：读取 `GET /api/v1/recording` 的实际文件、数量与记录错误。

页面与面板使用纯黑底色，Redbird 顶栏由紫色渐变至黑色。侧栏不显示编号，
选中项为全宽直角色条，上下细线标识状态，左右没有边框。主题使用本地 CSS，
不加载在线字体或外部视觉资源。

字段定义在 `src/domain/fields.ts`，同时服务正常显示和诊断。正常面板对未收到、陈旧、
语义无效或有效位缺失的字段显示“—”；诊断表保留有限原值并单列原因。新鲜度不代表
字段有效，也不代表控制权限。UGCTL 的泵/推进值是控制器输出，不能理解成执行器实测。

UGWRM schema3 同时显示 pitch、roll 和整次双轴校准；schema2 的 roll/总状态显示未知。
roll 百分比单独由 roll_valid 判断：PB3 释放点为 0%，PB5 释放点为 100%，
50% 是软件脉冲估算的行程中点，不表示艇体水平或编码器实测位置。
主页“双轴校准”及运行监控仅展示总状态、两轴阶段、失败原因和等待中立接管状态，不发送校准命令。

`App.vue` 只创建一次 `useStationState`，子面板接收同一份状态。浏览器使用本地
`performance.now()` 持续增加接收年龄；连接关闭立即将设备状态变为不可确认，
3.5 秒没有合法快照则关闭旧连接并重连，REST 初始请求有 3 秒超时。
短时曲线仅缓存在当前页面内存中；会话切换或板端时间回退会清空，失效段不连线，
控制目标仅在对应输出有效时显示。持久实验记录由核心完成。

开发运行：

    cd station/frontend
    npm install
    npm run dev

另一个终端在 station 目录运行：

    python -m groundstation

Vite 开发服务器把 /api 和 WebSocket 代理到 127.0.0.1:8000。生产构建：

    npm run build

生成的 dist 目录会被 FastAPI 自动托管。当前阶段仅绑定本机回环地址；局域网多机观察要等
鉴权、TLS 和观察者权限模型补齐后再开启。
